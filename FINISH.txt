Boltzmann-new -- the finished tree, restructured.

This folder is the whole library, already restructured to Maxwell's layout and
with section 6.1 applied.  It is a fresh folder rather than an edit of the old
one because the desktop bridge can write files but cannot DELETE them, and the
restructure is mostly deletions: test/ has to go, and the old folder had also
collected loose patches and duplicate downloads (boltzmann-1.hpp, rename-1.sh,
ADAPT-...-1.md) that would have stayed behind.

TWO STEPS, both in Explorer:

    1  delete  Downloads\projects\Boltzmann
    2  rename  Downloads\projects\Boltzmann-new   ->   Boltzmann

Then, from inside it:

    make
    make ranks

Nothing else.  There is no patch to apply and no git command needed.

THE MAKEFILES ARRIVED AS .new AND .gitignore AS gitignore.txt

Seventeen files named Makefile, and one dotfile.  The bridge refuses both
names.  Rename them in one go from inside the folder:

  PowerShell:
      Get-ChildItem -Recurse -Filter Makefile.new |
          ForEach-Object { Move-Item -Force $_.FullName ($_.FullName -replace '\.new$','') }
      Move-Item -Force gitignore.txt .gitignore

  Git Bash / WSL:
      find . -name 'Makefile.new' -execdir sh -c 'mv -f Makefile.new Makefile' \;
      mv -f gitignore.txt .gitignore

.gitignore only matters if you put the tree under git; the build does not
need it.

VERSION CONTROL, IF YOU WANT IT

boltzmann.bundle sits next to this folder in Downloads\projects and now holds
SIX commits -- the four from before plus 6.1 and the restructure.  Its last
commit is exactly this tree, so the simplest route is to skip the two steps
above entirely and instead, from Downloads\projects:

    git clone boltzmann.bundle Boltzmann2
    cd Boltzmann2
    git remote remove origin
    make && make ranks

That gives you the same tree WITH the history and with the Makefiles and
.gitignore already correctly named -- no renaming step at all.  Then delete
both Boltzmann and Boltzmann-new and rename Boltzmann2.
